# mdkanban カラム機能拡張 仕様書

## 目的・概要
mdkanban の **カラム（H2 見出し）** に対する操作機能を、既存のレーン機能（`SPEC_swimlane_rail.md` で実装済み）と同等の粒度・UI/UX で揃える。現状、カラムは Markdown を読み込んだ時点で生成されるが UI から追加・削除・並び替え・名前変更ができず、`SPEC.md` のスコープ外（「列＝H2 見出し」に対する操作のみ除外）にも明示されている。本仕様はそのスコープ外を撤回し、レーンと一貫した操作性をカラムにも提供する。さらに「特定カラムへ移動したカードを自動的に `- [x]` 化する」**自動チェック設定** をカラム単位で導入し、Done レーンに入れた瞬間に取り消し線で見えるという、カンバンで頻出する運用をワンクリックで実現する。

このドキュメントは、`mdkanban/SPEC.md`（本ツール本体仕様）と `mdkanban/SPEC_swimlane_rail.md`（スイムレーンサイドレールリファクタ仕様）の **差分仕様** として位置付ける。

## ゴール
- カラム（H2）に対して **F1 折りたたみ／F2 自動チェック／F3 並び替え／F4 追加／F5 削除／F6 リネーム** の6機能を、レーンと同じ UI 作法で提供する。
- 自動チェックを **同期型（B案）** で動かす。対象カラムにある間はカードのチェック状態を強制的に `[x]` 化し、対象外カラムへ戻したら `[ ]` に戻す。
- 操作の永続化方針を以下のとおり振り分ける:
  - 自動チェック対象カラム: frontmatter 独自キー `auto-check-columns:`
  - 折りたたみ状態: LocalStorage（ファイル横断・全ボード共通）
  - カラムの追加／削除／並び替え／リネーム: Markdown 上の H2 行そのもの（再シリアライズ）
- スイムレーンモード／通常モードの両方で機能し、スイムレーンモードでは **全レーン横断** で挙動が同期する。
- 既存の `lanes:` キーが無い／空のファイルや `auto-check-columns:` キーが無いファイルに対しては破壊的変更を行わない。

## 非ゴール
- カラムごとの WIP 制限（カード数上限）
- カラムごとの色分け／アイコン
- カラムのアーカイブ（隠しつつデータは残す）
- 「カラムが空になったら自動的に削除」のような自動収束ロジック
- 自動チェックの**逆方向**（チェック済みカードを Done 以外に動かしたとき自動で別状態にする等の独自カスタムフロー）。本仕様の自動チェックはあくまで「対象カラム所属＝チェック ON、対象外＝チェック OFF」の純粋な同期。

## 用語定義
| 用語 | 定義 |
|---|---|
| カラム | Markdown の H2 見出し（`## TODO` 等）と、その下に並ぶカード群の集合。`board.columns[i]` と1対1対応。 |
| カラムヘッダ | カラム最上部のラベル領域。カラム名＋カード件数＋ホバー時の操作メニュー（◀▶✎☑🗑）を持つ。 |
| カラム操作メニュー | カラムヘッダ hover／focus-within で右側にフローティング表示される操作ボタン群。レーンの `.swimlane-actions` と同じ作法。 |
| 自動チェック対象カラム | frontmatter の `auto-check-columns:` 配列に列挙されたカラム名。所属カードは `card.checked = true` に強制される。 |
| 自動チェック | カラムへのカード所属変化（移動／追加／作成／編集確定）を契機に `card.checked` を強制更新する同期型ロジック。 |
| 折りたたみカラム | `state.collapsedColumns` に列挙されたカラム名。サイドレール風の縦書きヘッダのみが残り、カード群は非表示。 |
| 縦書きヘッダ | 折りたたみ時の細幅（40〜48px）カラム表示。カラム名を `transform: rotate(-90deg)` で縦表示する。 |
| 移動先選択モーダル | カラム削除時に「所属カードの退避先カラム」をユーザーに選択させる確認モーダル。 |

## 機能要件

### F1. カラム折りたたみ

#### 概要
カラムヘッダの折りたたみトグルで、そのカラムを **40〜48px幅の縦書きサイドレール状態** に切替可能とする。レーンサイドレール（`SPEC_swimlane_rail.md`）の挙動をカラム軸（縦方向のレーンに対して、横方向のカラム）にも適用する。

#### 詳細
- F1-1: **トグル UI**: 各カラムヘッダの左端に折りたたみトグル（`▼` / 折りたたみ時 `▶`）を配置する。クリック／キーボード（Enter／Space）で `state.collapsedColumns` の対応エントリをトグルする。
- F1-2: **折りたたみ時の見た目（縦書きカラム）**:
  - 幅 40〜48px 程度（最終ピクセル値は実装側で決めてよいが、縦書き名・カウントが収まること）。レーンサイドレール幅（48px）と揃えるのが望ましい。
  - 内部レイアウト（上から下）:
    1. 折りたたみトグル `▶`（最上部）
    2. **回転カラム名**（`transform: rotate(-90deg)`、`white-space: nowrap`、`text-overflow: ellipsis`）
    3. **カード件数バッジ**（最下部、円形バッジ・径22〜26px）
  - カラム操作メニュー（◀▶✎☑🗑）はホバー時のみ右下／右側にフローティング表示する（レーンと同じ）。
- F1-3: **永続化**: `state.collapsedColumns` を `Set<string>`（カラム名）として保持し、`localStorage.mdkanban.collapsedColumns` に JSON 配列で保存する。`mdkanban.collapsedLanes` と同じく **ファイル横断・全ボード共通**（個別ファイル単位の保持はしない）。
- F1-4: **スイムレーンモード時の同期**: スイムレーンモード（`useSwimlanes=true`）で `## TODO` を畳むと、**全レーンの TODO 列が一斉に畳まれる**。レーン別の独立した折りたたみ状態は持たない。
- F1-5: **通常モード時**: 折りたたみカラムの幅変化に追従して、隣のカラムが詰めて表示される（横並びレイアウトのまま）。
- F1-6: **カードのドロップ可否**: 折りたたみ中のカラムには **DnD でカードをドロップできない**（操作不可表示）。展開してから移動する設計とする。
- F1-7: **キーボード操作・ARIA**:
  - トグルボタンに `aria-expanded`（展開時 `true` / 折りたたみ時 `false`）を付与
  - `aria-label` は `${カラム名} 列の折りたたみを切替`
  - Tab フォーカス時に `:focus-visible` のアウトラインを表示
- F1-8: **「+ カード追加」ボタンの扱い**: 折りたたみ中のカラム／セルでは「+ カード追加」ボタンは描画しない（縦書きレールに収まらないため）。展開後に再露出する。

### F2. カラム自動チェック設定（同期型）

#### 概要
`auto-check-columns:` 配列に列挙されたカラムに **所属する間** はカードを `- [x]`（`card.checked = true`）に強制し、外れたら `- [ ]` に戻す。Done 列を作って捨てる、リリース済み列に積むといった頻出運用を、ユーザーが手動でチェックボックスを操作することなく実現する。

#### 動作モード（同期型 = B案）
カードのチェック状態は、現在所属しているカラムが `auto-check-columns:` に含まれているかどうかで一意に決まる。これを以下の **すべての契機** で再評価する。

| 契機 | 期待される結果 |
|---|---|
| カードを DnD で対象カラムに移動 | `card.checked = true` に変更し、再シリアライズ後の md は `- [x]` |
| カードを DnD で対象カラムから他カラムに移動 | `card.checked = false` に変更し、`- [ ]` |
| 対象カラムで「+ カード追加」 | 新規カードの初期 `checked = true` |
| 対象外カラムで「+ カード追加」 | 新規カードの初期 `checked = false`（既存仕様どおり） |
| モーダル編集モードで保存 | カード自身の checked 値を、所属カラムの自動チェック状態で強制上書き |
| インライン編集（タイトル変更）で確定 | カード自身の checked 値を、所属カラムの自動チェック状態で強制上書き |
| カラムを `auto-check-columns:` に追加（F2-A） | そのカラムの全カードを `checked = true` に一括変更 |
| カラムを `auto-check-columns:` から外す（F2-A） | そのカラムの全カードを `checked = false` に一括変更（既存の手動チェックも失われる点はユーザーに説明する必要なし＝同期型仕様） |
| カードのカラム間移動（カラム並び替え F3 でカード自体は動かない） | カラム順を変えてもカード所属は変わらないので checked も変えない |

#### F2-A. 設定 ON/OFF UI
- F2-A-1: **エントリポイント**: カラムヘッダの操作メニューに **`☑ 自動チェック`** トグルボタンを追加する（◀▶ 並び替え／✎ リネーム／🗑 削除と並列）。
- F2-A-2: **押下時の挙動**:
  - 当該カラム名が `auto-check-columns:` に **含まれていなければ追加**し、所属する全カードを `checked = true` に同期する。
  - 既に含まれていれば **除去**し、所属する全カードを `checked = false` に同期する。
- F2-A-3: **視覚状態**: ON 中はトグルが押下状態（`aria-pressed="true"` ＋スタイル変化）になる。展開時のカラムヘッダにも控えめなマーカー（例: ヘッダ右端に小さなチェックアイコン `☑`）を出して、メニューを開かなくても ON 状態が一目で分かること。
- F2-A-4: **`auto-check-columns:` 永続化**: ON/OFF 切替の都度、frontmatter の `auto-check-columns:` 配列を更新し、再シリアライズ＆自動保存トリガーを発火する。
- F2-A-5: **空配列への退化**: 全カラムをトグル OFF にして配列が空になった場合は **`auto-check-columns:` キーごと frontmatter から削除する**（空のままキーを残さない。`lanes:` の挙動と同じ方針）。
- F2-A-6: **存在しないカラム名の自動掃除**: ファイルロード時、`auto-check-columns:` 配列内に現在の `board.columns[].name` に存在しないカラム名があれば、警告を出さず黙って除去して再シリアライズする（孤児エントリの自動掃除）。
- F2-A-7: **カラムリネーム時の追従**: F6 でカラム名 `Done → リリース済み` にリネームすると、`auto-check-columns:` 配列内の `Done` も `リリース済み` に同期して書き換える（後述 F6-7）。
- F2-A-8: **カラム削除時の追従**: F5 でカラムを削除すると、`auto-check-columns:` 配列からそのカラム名を除去する（後述 F5-9）。

#### F2-B. データモデル
- frontmatter キー `auto-check-columns` は **YAML 配列（ブロックスタイル）** で書く:
  ```yaml
  auto-check-columns:
    - Done
    - リリース済み
  ```
- `lanes:` と同じ書き出し規約に従う:
  - 出現順は board 内の保持順序を尊重する（=トグル ON した順）
  - フロー形式 `[a, b]` は書き出さない（読み取りでは `lanes:` と同様に緩く受け付ける）
  - 値が予約文字を含む場合のみダブルクォートで囲む（`yamlScalarValue` を流用）
- frontmatter に当該キーが無い／空の場合は機能オフ。
- スイムレーンモードでも **カラム単位** の設定なので全レーン共通（レーン別に分けない）。

### F3. カラム並び替え

#### 概要
カラム（H2 見出し）の表示順を UI から変更可能とする。Markdown 上の H2 順序が物理的に入れ替わる。

#### 詳細
- F3-1: **操作 UI**: カラムヘッダの操作メニューに `◀ 左へ` `▶ 右へ` ボタンを配置する（レーンの `▲▼` を 90度回転させた方向と読み替える）。
- F3-2: **DnD 並び替え**: カラムヘッダ全体（`.kanban-column-header` 相当）を `draggable="true"` にし、別カラムのヘッダ上にドロップで順序入れ替えできる。レーンと同じく `is-column-drop-target` 等のハイライトクラスでドロップ予定位置を視覚化する。
- F3-3: **境界制御**: 先頭カラムの `◀` ボタン、末尾カラムの `▶` ボタンは `disabled` にする。
- F3-4: **再シリアライズ**: 並び替え確定後、`board.columns` 配列を順序変更し、Markdown 上の H2 ブロックも物理的に入れ替わる（`## TODO` `## Doing` `## Done` → `## Doing` `## TODO` `## Done` 等）。各カラム配下のカード群はそのカラムにくっついて移動する。
- F3-5: **スイムレーンモード時の同期**: 全レーン横断で同期する。`## TODO` を `## Doing` の右に移動すると、各レーンの TODO 列も Doing の右に移る。
- F3-6: **a11y**: 並び替え完了時に `aria-live="polite"` で「カラム「<名前>」を <左/右> に移動しました」とアナウンス。

### F4. カラム追加

#### 概要
ボード末尾にカラムを追加できるようにする。レーン追加（`+ レーン追加`）と同じ作法のインラインフォーム方式。

#### 詳細
- F4-1: **エントリポイント**:
  - 通常モード: 既存ボードの **右端**（最後のカラムの右）に `+ カラム追加` ボタンを配置する。
  - スイムレーンモード: 列ヘッダ行の右端に `+ カラム追加` ボタンを配置する。スイムレーンモードでも既存の「+ レーン追加」ボタン（縦軸方向、`renderAddLaneControl`）と干渉しない位置とする（レーン追加は最下行末尾、カラム追加は列ヘッダ行末尾）。
- F4-2: **入力フォーム**: ボタン押下でインライン `<input>` を表示する（レーン追加 UI と同じ作法）。Enter で確定、Esc／キャンセルボタンで破棄。
- F4-3: **バリデーション**:
  - 空文字は不可（インラインエラー: `カラム名を入力してください`）。
  - 既存カラム名と重複する場合は不可（インラインエラー: `すでに存在するカラム名です`）。`board.columns[].name` との完全一致で判定。
  - カラム名の文字種制約: **空でないこと**のみを必須とする。レーン名（`[A-Za-z0-9_\-...]+`）と異なり、カラム名はスペース・記号を許容する（`## In Progress` のような既存運用との互換性を優先）。改行文字とタブのみ禁止。
- F4-4: **追加位置**: `board.columns` の末尾に新規カラムを `{ name, cards: [] }` で追加。Markdown 上は最後の `## ...` ブロックの後ろに `## <新カラム名>` が追記される。
- F4-5: **再シリアライズ＆自動保存**: 追加後 `reserializeAndPersist` → `markDirty` → `renderBoard` → `triggerAutoSave` の順。
- F4-6: **a11y**: 追加完了で `aria-live="polite"` に「カラム「<名前>」を追加しました」とアナウンス。

### F5. カラム削除

#### 概要
カラムを削除できるようにする。所属カードがあった場合は **削除確認モーダル** で「移動先カラム」を選択させ、全カードを単一の選択先カラムに退避してからカラムを除去する。

#### 詳細
- F5-1: **エントリポイント**: カラムヘッダの操作メニューに `🗑 削除` ボタンを配置する。
- F5-2: **削除確認モーダルの表示条件**:
  - 所属カードが0件 → `window.confirm` 相当の単純な確認のみ（「カラム「<名前>」を削除します。よろしいですか？」）。
  - 所属カードが1件以上 → **専用モーダル**（移動先選択 UI 付き）を表示する。
- F5-3: **モーダル構造**（専用モーダル）:
  - タイトル: `カラム「<名前>」を削除`
  - 説明文: `所属する <N> 件のカードを別のカラムに移動してから削除します。移動先を選択してください。`
  - 移動先選択 UI: 削除対象以外の全カラムを **ラジオボタンまたはセレクトプルダウン** で列挙（実装はどちらでもよいが、3カラム以下ならラジオが推奨）。デフォルト選択は「現在のカラムの直前のカラム」（先頭カラムを削除する場合は「直後のカラム」）。
  - 自動チェック対象カラムが移動先に含まれる場合の注意書き（任意）: `※ 「<移動先名>」は自動チェック対象です。移動するカードは [x] になります。`
  - フッター: `削除して移動` ボタン（プライマリ）／`キャンセル` ボタン
  - `Esc`／背景クリックでキャンセル
- F5-4: **最後のカラムの削除制限**: 削除対象が **最後のカラム**（=`board.columns.length === 1`）の場合は削除不可。`🗑` ボタンを `disabled` にし、`title` 属性で `カラムは1つ以上必要です` と注釈する。
- F5-5: **削除実行**: 確定後、以下を順番に実行する:
  1. 削除対象カラムの全カードを移動先カラムの末尾に移動（`splice` で取り出して `push`）
  2. 移動先カラムが自動チェック対象なら、移動した各カードの `card.checked = true` に同期。対象外なら `false` に同期（F2 同期型ロジック）
  3. `board.columns` から削除対象カラムを除去
  4. `auto-check-columns:` から削除対象カラム名を除去（F2-A-8）
  5. 折りたたみ状態 `state.collapsedColumns` から削除対象カラム名を除去
  6. 再シリアライズ＆自動保存
- F5-6: **スイムレーンモード時の挙動**: 全レーンの当該カラムが消える。各レーンに属していたカードは **レーンを保ったまま** 移動先カラムに集約される（`card.lane` は変更されない）。スイムレーン横断でひとつのモーダルだけ出し、ユーザーは1回の操作で全レーン分の退避先を決める（レーンごとに別の退避先を選ぶ UI は出さない）。
- F5-7: **a11y**: 削除完了で `aria-live="polite"` に「カラム「<名前>」を削除しました（<N> 件のカードを「<移動先名>」に移動）」とアナウンス。
- F5-8: **キーボード操作**:
  - モーダルを開いた直後、移動先選択 UI の最初の選択肢にフォーカス
  - Tab で `削除して移動` → `キャンセル` の順に到達
  - `Enter` でデフォルトボタン（`削除して移動`）を発火
  - `Esc` でキャンセル
- F5-9: **`auto-check-columns:` 同期**（再掲・F2-A-8）: 削除対象カラム名が `auto-check-columns:` に含まれていれば配列から除去する。除去結果が空配列ならキーごと frontmatter から削除する。

### F6. カラムリネーム

#### 概要
カラムヘッダのカラム名をインライン編集で変更できるようにする。レーンリネームと同じ作法。

#### 詳細
- F6-1: **エントリポイント**:
  - カラムヘッダの操作メニューに `✎ リネーム` ボタン
  - カラム名部分のダブルクリック
  - のいずれでも編集モードに入れる（レーンと同じ）。
- F6-2: **インライン編集**: カラム名 `<span>` を `<input type="text">` に置換し、現在の名前を初期値として全選択フォーカス。
- F6-3: **確定操作**:
  - `Enter`: 確定
  - `Esc`: キャンセル（変更破棄）
  - `blur`: 確定
- F6-4: **バリデーション**: F4-3 と同じ（空不可・他カラムと重複不可・改行とタブ不可）。違反時はトーストで通知（`カラム名は空にできません` / `すでに存在するカラム名です`）し、編集モードを継続する。
- F6-5: **同名（変更なし）の確定**: 確定値が元の名前と同じなら何もしない（再シリアライズも自動保存もしない）。
- F6-6: **再シリアライズ**: `board.columns[i].name` を新名に置換し、Markdown 上の対応 H2 行が `## <旧名>` → `## <新名>` に書き換わる。
- F6-7: **`auto-check-columns:` 追従**（F2-A-7 再掲）: リネーム前の名前が `auto-check-columns:` に含まれていた場合、配列内の該当エントリを新名に置換する。
- F6-8: **`state.collapsedColumns` 追従**: リネーム前の名前が折りたたみ集合に含まれていた場合、新名に置換する（同名 Set 操作）。LocalStorage にも反映する。
- F6-9: **a11y**: 確定後、`aria-live="polite"` に「カラム「<旧名>」を「<新名>」に名前変更しました」とアナウンス。

## データモデル変更

### frontmatter スキーマ拡張

#### `auto-check-columns:` キー（新規）
- 型: 文字列の YAML 配列（ブロックスタイル）
- 値: 自動チェック対象とするカラム名の配列。順序は重要ではないが、トグル ON 順を尊重して保存する。
- パース時:
  - 重複は最初の出現のみ採用、以降は黙って除去（`lanes:` と同じ）
  - フロー形式 `[a, b]` も読み取り時は緩く受け付ける（書き出しはブロック形式に統一）
  - 値が空文字列・空白のみのエントリは無視
  - 配列要素のうち、現在の `board.columns[].name` に存在しないものはロード時に自動掃除
- シリアライズ時:
  - 値が空配列ならキーごと frontmatter から削除
  - `lanes:` キーが既にある場合は `auto-check-columns:` をその後ろ（または前後どちらでもよい・**他キーの順序を破壊しないこと**を最優先）に配置する
  - YAML 予約文字を含む場合のみダブルクォートで囲む（`yamlScalarValue` を流用）

#### 例
```yaml
---
kanban-plugin: basic
lanes:
  - バックエンド
  - フロントエンド
auto-check-columns:
  - Done
  - リリース済み
---
```

#### `lanes:` キーとの相互作用
- `auto-check-columns:` は **カラム軸** の設定であり、`lanes:` の有無（スイムレーンモードかどうか）に依存しない。
- 通常モード（`lanes:` 無し）でも `auto-check-columns:` 単独で機能する。
- スイムレーンモードでも `auto-check-columns:` は **全レーン共通** で適用される。

### LocalStorage キー（新規）

#### `mdkanban.collapsedColumns`
- 型: JSON 配列（`string[]`）
- 内容: 折りたたみ中のカラム名の集合
- スコープ: **ファイル横断・全ボード共通**（`mdkanban.collapsedLanes` と同じ方針）
- 既存キー一覧 `STORAGE_KEYS` に追加する想定。

```js
{
  // 既存
  content: 'mdkanban.lastContent',
  fileName: 'mdkanban.lastFileName',
  theme: 'mdkanban.theme',
  density: 'mdkanban.density',
  collapsedLanes: 'mdkanban.collapsedLanes',
  // 新規
  collapsedColumns: 'mdkanban.collapsedColumns'
}
```

### state 拡張

```js
const state = {
  // 既存
  ...
  collapsedLanes: new Set(),
  // 新規
  collapsedColumns: new Set()  // 折りたたみ中のカラム名
};
```

`board` オブジェクトには **新規プロパティを追加せず**、`auto-check-columns:` 配列は `board.autoCheckColumns: string[]` として保持する（`hasLanesKey` / `lanesWhitelist` / `otherFrontmatterRaw` と同じ層）。シリアライズ時は `serializeBoard` の frontmatter 再構築ブロックに `auto-check-columns:` の出力ロジックを足す。

### Markdown 上の H2 順序

- カラムの追加／削除／並び替え／リネームは **Markdown 上の H2 行を物理的に変更する**。
- H2 とその直下のカード群（およびサブタスク・bodyParts）は不可分のブロックとして移動・削除される。
- 既存の `serializeBoard` ロジックを流用し、`board.columns` の配列順がそのまま H2 の出現順になる。

## 移動と自動チェックの相互作用（F2 詳細フロー）

カードのチェック状態（`card.checked`）を再評価する経路は、以下のすべて。各経路で **共通ヘルパー** を呼ぶ実装を推奨する（仕様としては命名は問わない・観測可能な振る舞いを規定する）。

| 経路 | トリガ | 期待される動作 |
|---|---|---|
| F7 DnD（カード移動） | `moveCard` 内の最後 | 移動先カラム名が `auto-check-columns:` に含まれていれば `card.checked = true`、含まれていなければ `card.checked = false` に上書き |
| F10 「+ カード追加」 | `addNewCard` 内の初期化 | 追加先カラムが対象なら `checked = true`、対象外なら `false`（既存仕様の `false` を維持） |
| F9 モーダル編集 確定 | `commitModalEditMode` の最後 | 編集後の所属カラムで再評価（モーダル編集ではカラム移動は起こらないが、防御的に再評価） |
| F9 インライン編集 確定 | `commitInlineEdit` の最後 | 同上 |
| F2-A 自動チェック ON 切替 | F2-A-2 の追加経路 | そのカラムの全カードを `checked = true` に一括変更 |
| F2-A 自動チェック OFF 切替 | F2-A-2 の除去経路 | そのカラムの全カードを `checked = false` に一括変更 |
| F5 カラム削除 | 退避先カラムへ移動した直後 | 退避先で再評価。退避先が対象なら `true`、対象外なら `false` |
| F4 カラム追加 | 追加直後 | 新規カラムは空なので無処理 |
| F3 カラム並び替え | 並び替え直後 | カードの所属は変わらないので checked は変えない |

### Markdown 出力時の `- [x]` / `- [ ]` 整合性
- 自動チェックは `card.checked` プロパティを書き換えるだけで、`serializeBoard` の既存ロジック（`card.checked === true` → `- [x] `, `false` → `- [ ] `, `null` → `- `）にそのまま乗る。
- `card.checked === null`（=チェックボックス無し `- テキスト` 形式）のカードを自動チェック対象カラムに移動した場合は **`true` に昇格** する（`- [x] テキスト` 形式に書き換わる）。同期型仕様の自然な帰結として明示する。
- 自動チェック対象外カラムへ移動した `null` 由来のカードは `false` になる（`- [ ] テキスト` 形式に書き換わる。元の `- テキスト` 形式は失われる）。これは **既知の仕様トレードオフ** とする（ユーザーが意図的にチェックボックス無し書式を使っていた場合の互換性は犠牲にする）。
- ユーザーへのドキュメント案内: FAQ または HowTo に「自動チェック対象カラムにあるカードは必ず `- [x]` に統一されます」と1行明記する。

## レーンモードとの相互作用（A6 の詳細）

| 機能 | 通常モード | スイムレーンモード |
|---|---|---|
| F1 折りたたみ | 単一行カラムが細幅化 | 全レーン横断で当該カラム列が一斉に細幅化 |
| F2 自動チェック | 単一行カラムに適用 | 全レーンの当該カラムに適用（カラム単位の設定なので） |
| F3 並び替え | カラムが横方向に入れ替わる | 全レーンで一斉にカラム列が入れ替わる（`board.columns` を1度入れ替えれば描画上も全レーン同期） |
| F4 追加 | 末尾に新規カラム1本が追加 | 全レーンに新規カラム列が出現（各セルは空） |
| F5 削除 | 1カラムが消える＋カードが移動先に集約 | 全レーンの当該カラムが消える＋各レーンのカードはレーンを保ったまま移動先カラムに集約 |
| F6 リネーム | カラム名のみ変更 | 全レーンで一斉に当該カラム列のヘッダ名が変わる（実体は `board.columns[i].name` 1箇所変更） |

### スイムレーンモードでの DOM レンダリング順序（F4 追加時）
- `renderSwimlaneBoard` の列ヘッダ行と各 `.swimlane-row` の双方に新カラムのセルが追加される。
- スイムレーンの折りたたみ状態 `state.collapsedLanes` とカラムの折りたたみ状態 `state.collapsedColumns` は独立に動作する。両方が交差した場合（折りたたみレーン × 折りたたみカラム）は両方の畳み視覚が重なる（カラム細幅 × レーン折りたたみ非表示行）。

### スイムレーンモードでカラム削除した時の DnD ハンドル/データ整合性
- F5 でカラム削除すると `data-col-index` の番号が振り直される。`board.columns` を再 splice して `assignIds` を呼び直す（既存仕様の DnD ハンドラ再アタッチで対応する）。

## 既存仕様との非互換と移行戦略

### 既存仕様への影響
- `SPEC.md` の「スコープ外」に記載されている **「列（H2 見出し）の追加／削除／列名の編集」** は本仕様の F4／F5／F6 で **撤回** される。`SPEC.md` 側のスコープ外記述は将来更新時に整理する（本仕様書は差分仕様として独立配置するため、`SPEC.md` 本体は触らないことを基本とする）。
- `SPEC.md` AC50 が言及する「スコープ外リスト」の整合性は、本仕様の存在で部分的に古くなる。`SPEC.md` 本体の AC50 自体は引き続き有効（カード本文編集が F9 に格上げされている記述）であり、本仕様はそれをさらに上書きしない。

### 既存 Markdown ファイルへの非互換
- **無い**。`auto-check-columns:` キーが無いファイル・`lanes:` キーが無いファイル・既存のカラム構造のみのファイルすべて、ロード後の挙動は変わらない（カラム機能は UI 上で追加されるが、永続化される副作用は発生しない）。

### 移行戦略
- 既存ユーザーは何もしなくても新機能が利用可能になる。
- 自動チェックを使い始めた瞬間に frontmatter に `auto-check-columns:` キーが追加され、Obsidian Kanban で同じファイルを開いた場合は **未知の frontmatter として無視される**（緩い互換、`lanes:` と同じ方針）。
- カラム追加／削除／並び替え／リネームは Markdown 上の H2 行を物理的に変更するため、Git 等のバージョン管理下で diff が大きく出る点はユーザーに案内する（FAQ で言及）。

### Obsidian Kanban 互換性
- `auto-check-columns:` キーは Obsidian Kanban の標準仕様には存在しない（mdkanban 独自拡張）。Obsidian 側では未知のキーとして無視されるため、ファイル内容を破壊しない。
- カラム並び替え／リネーム／追加／削除はすべて H2 行の直接編集なので、Obsidian Kanban 側でも問題なく開ける。
- 自動チェックによって `- [x]` 化された行は、Obsidian Kanban 側でも単に「完了タスク」として表示される（互換性あり）。
